# ТЗ: бэкенд для вишлиста на день рождения

## 1. Цель

Простой публичный бэкенд для лендинга-вишлиста. Гости открывают страницу, видят список подарков с ценой за штуку и остатком, нажимают «Беру», выбрав количество — остаток и статус кнопки должны обновляться **у всех гостей одинаково** (общее состояние, не localStorage).

Фронтенд уже готов (`wishlist.html`) и обращается к бэкенду через `fetch` по контракту ниже. Заменить нужно только `API_BASE_URL` в начале файла на реальный адрес после деплоя.

## 2. Модель данных

Одна таблица/коллекция `items`:

| поле | тип | описание |
|---|---|---|
| `id` | string, PK | slug подарка, напр. `massage` |
| `name` | string | название |
| `price` | number \| null | цена за штуку, `null` если не указана |
| `currency` | string | по умолчанию `GEL` (лари) |
| `total_qty` | integer | сколько штук доступно всего; `-1` = бесконечно |
| `taken_qty` | integer | сколько уже занято, стартует с `0` |

Сид-данные (актуальный вишлист):

```json
[
  { "id": "korzina",   "name": "Корзина на тему",                         "price": null, "total_qty": 2,  "taken_qty": 0 },
  { "id": "massage",   "name": "Массаж",                                   "price": 130,  "total_qty": 1,  "taken_qty": 0 },
  { "id": "print",     "name": "Большой принт (для дома)",                 "price": 100,  "total_qty": 8,  "taken_qty": 0 },
  { "id": "yoga",      "name": "Йога по субботам в 11:00",                 "price": null, "total_qty": -1, "taken_qty": 0 },
  { "id": "bread",     "name": "Хлеб хоккайдо в Пальпе (буханка в неделю)","price": 8,    "total_qty": -1, "taken_qty": 0 },
  { "id": "rehab",     "name": "Занятие с реабилитологом-тренером",        "price": 150,  "total_qty": 1,  "taken_qty": 0 },
  { "id": "psy",       "name": "Занятие с психологиней",                   "price": 160,  "total_qty": 1,  "taken_qty": 0 },
  { "id": "tattoo",    "name": "Новая татуировка",                         "price": 150,  "total_qty": 1,  "taken_qty": 0 },
  { "id": "sneakers",  "name": "Копилка на кроссовки",                     "price": null, "total_qty": -1, "taken_qty": 0 }
]
```

`price: null` — показывать на фронте как «сумма по договорённости», но кнопка и логика занятия работают так же.

## 3. API

### `GET /api/items`
Возвращает текущее состояние всех подарков.

Ответ `200`:
```json
{ "items": [ { "id": "massage", "name": "Массаж", "price": 130, "currency": "GEL", "total_qty": 1, "taken_qty": 0 }, ... ] }
```

### `POST /api/items/:id/claim`
Тело запроса:
```json
{ "qty": 1 }
```

Логика:
1. Найти item по `id`. Если нет — `404 { "success": false, "message": "not_found" }`.
2. Посчитать `remaining = total_qty === -1 ? Infinity : total_qty - taken_qty`.
3. Если `remaining <= 0` — вернуть `409 { "success": false, "message": "already_taken", "taken_qty": ..., "total_qty": ... }`.
4. Если `qty > remaining` — обрезать `qty` до `remaining` (не роняем запрос, просто не даём уйти в минус).
5. Атомарно инкрементировать `taken_qty += qty` (см. п.4 «конкурентность»).
6. Вернуть `200 { "success": true, "id": ..., "taken_qty": ..., "total_qty": ..., "given_qty": qty }`.

Никакой авторизации не нужно — эндпоинт публичный (это вишлист для гостей, не приватные данные).

## 4. Конкурентность (важно)

Два гостя могут нажать «Беру» почти одновременно на последний свободный слот. Инкремент `taken_qty` должен быть атомарным:
- SQL: `UPDATE items SET taken_qty = taken_qty + :qty WHERE id = :id AND (total_qty = -1 OR taken_qty + :qty <= total_qty)`, проверить `rowCount`; если 0 — значит не хватило слотов, вернуть `409`.
- Если используется файл/JSON вместо БД — обязательно взять lock (mutex) на запись.

## 5. Технологии — на выбор агента

Любой вариант подходит, задача маленькая:
- **Node.js + Express + SQLite (better-sqlite3)** — самый простой, один процесс, БД — файл. Деплой на Render/Railway/Fly.io.
- **Node.js + Express + Supabase/Postgres** — если хочется managed БД.
- Не использовать Google Apps Script — уже есть отдельный fallback-вариант в `Code.gs`, он не требует этого ТЗ.

Требования к деплою:
- HTTPS-эндпоинт, доступный публично.
- CORS открыт для всех источников (`Access-Control-Allow-Origin: *`), т.к. лендинг может быть на другом домене/просто открываться как файл.
- Сид базы данных значениями из п.2 при первом запуске (миграция/seed-скрипт).

## 6. Что фронтенд ожидает от кнопки «Беру»

Уже реализовано в `wishlist.html`, для справки:
1. При загрузке страницы — `GET /api/items`, отрисовать остаток `total_qty - taken_qty` и заблокировать кнопку, если остаток `0`.
2. У каждой карточки — числовой селектор количества (1..remaining, для бесконечных — 1..20).
3. По клику «Беру» — `POST /api/items/:id/claim`, при `success: true` кнопка красится (сменить класс) и текст меняется на «Занято» (полностью, если остаток стал 0) либо остаётся «Беру», но остаток обновляется.
